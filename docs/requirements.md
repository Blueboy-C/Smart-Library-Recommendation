# 智慧图书馆个性化学习推荐系统 — 需求分析文档

---

## 1. 项目概述

### 1.1 项目背景

高校内部长期运行着多套独立的信息系统：图书馆管理系统沉淀了学生借阅行为数据，教务系统积累了选课与成绩数据。这些数据各自孤立，未被有效打通和利用。学生面对百万馆藏无从下手，选课决策缺乏个性化依据，教师和管理层对学生的真实学习兴趣分布缺乏量化视角。

本课题旨在打通这两条核心数据线，通过AI算法为每位学生构建学习兴趣画像，实现图书、课程、学术活动的个性化推荐，并为教师和管理层提供学生兴趣分布的数据看板。

### 1.2 项目定位

一个面向高校的**Web端个性化学习推荐平台**。以图书馆借阅数据为主干、教务选课与成绩数据为增强，通过传统推荐算法（协同过滤 + 内容推荐）完成候选召回与排序，通过大语言模型（LLM）实现智能推荐解释、学习路径规划、跨领域兴趣发现、对话助手、教师洞察报告和语义检索等智能化功能。为学生提供"能理解、能对话、能解释"的个性化推荐，为教师提供数据驱动的学生兴趣洞察。

### 1.3 目标用户

| 角色 | 核心诉求 |
|------|----------|
| **学生** | 发现适合自己的图书、课程、学术活动；理解推荐理由；自主规划学习路径 |
| **教师/辅导员** | 掌握所管学生群体的兴趣分布与变化趋势；发现资源匹配缺口；识别需要关注的异常学生群体 |

### 1.4 核心目标

推荐准确率（Top-10推荐中用户正向反馈占比）不低于 **75%**。

## 2. 数据源定义

### 2.1 可用数据源

经前期调研，可实际获取的数据源限定为以下三类：

| 序号 | 数据源 | 可得性 | 信号强度 | 覆盖范围 |
|------|--------|--------|----------|----------|
| 1 | 图书馆借阅数据 | 高（现有系统） | 极高 | 有借阅行为的学生 |
| 2 | 教务选课与成绩数据 | 高（现有系统） | 极高 | 全校学生 |
| 3 | 学生基本信息 | 高（现有系统） | 低 | 全校学生 |

以下数据源不可得，不纳入系统设计：
- 一卡通消费数据（与学习场景关联弱，覆盖率低）
- 图书馆OPAC检索日志
- 在线学习平台行为数据
- 学术数据库访问日志
- 图书馆门禁与座位预约数据
- 讲座/学术活动报名数据

### 2.2 数据源详述

#### 2.2.1 图书馆借阅数据

| 字段 | 类型 | 说明 |
|------|------|------|
| 学号 | 字符串 | 学生唯一标识 |
| 图书ID | 字符串 | 图书唯一标识 |
| 书名 | 字符串 | 用于关键词提取 |
| 中图分类号 | 字符串 | 用于知识领域映射 |
| 作者 | 字符串 | 辅助信息 |
| 出版社 | 字符串 | 辅助信息 |
| 借阅日期 | 日期 | 用于时段分析 |
| 归还日期 | 日期 | 计算借阅时长 |
| 续借次数 | 整数 | 反映阅读深度 |

衍生字段：
- 借阅时长 = 归还日期 - 借阅日期
- 借阅频次 = 学期维度聚合的借阅次数

#### 2.2.2 教务选课与成绩数据

| 字段 | 类型 | 说明 |
|------|------|------|
| 学号 | 字符串 | 学生唯一标识 |
| 课程编号 | 字符串 | 课程唯一标识 |
| 课程名称 | 字符串 | 用于关键词提取和领域映射 |
| 课程类型 | 枚举 | 必修课 / 选修课 |
| 开课学院 | 字符串 | 判断跨学科选修 |
| 成绩 | 数值 | 映射为掌握度 |
| 学期 | 字符串 | 时序分析 |

衍生字段：
- 掌握度 = 成绩分档（90+→精通 / 80-89→熟练 / 60-79→了解 / <60→薄弱）

#### 2.2.3 学生基本信息

| 字段 | 类型 | 说明 |
|------|------|------|
| 学号 | 字符串 | 唯一标识，数据关联主键 |
| 年级 | 字符串 | 冷启动和群体分层 |
| 专业 | 字符串 | 冷启动和领域关联 |
| 性别 | 枚举 | 可选维度的群体统计 |

### 2.3 资源数据

行为数据（借阅记录、选课成绩）告诉系统"学生是什么样的人"，资源数据告诉系统"有哪些东西可以推荐"。三类资源数据缺一不可。

#### 2.3.1 馆藏书目元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| 图书ID | 字符串 | 唯一标识，与借阅记录关联 |
| 书名 | 字符串 | 关键词提取 |
| 作者 | 字符串 | 辅助信息 |
| 出版社 | 字符串 | 辅助信息 |
| 出版年份 | 整数 | 时效性判断 |
| 中图分类号 | 字符串 | 知识领域映射 |
| 内容摘要/目录 | 文本 | TF-IDF关键词提取的核心文本来源 |
| 馆藏数量 | 整数 | 可借状态判断 |
| 在馆数量 | 整数 | 已被借出的书可推荐预约 |

**数据来源**：图书馆管理系统MARC格式导出，可得性高。

#### 2.3.2 课程元数据

推荐系统需要知道全校开设了哪些选修课、每门课讲什么，而不只是学生已经选了什么课。

| 字段 | 类型 | 说明 |
|------|------|------|
| 课程编号 | 字符串 | 唯一标识 |
| 课程名称 | 字符串 | 关键词提取 |
| 课程类型 | 枚举 | 必修/选修/公选 |
| 开课学院 | 字符串 | 跨学科推荐判断 |
| 课程简介/教学大纲 | 文本 | 内容推荐的核心文本来源 |
| 先修要求 | 文本/列表 | 学习路径规划的判断依据 |
| 学分 | 整数 | 辅助信息 |
| 开课学期 | 字符串 | 推荐时机判断 |

**数据来源**：教务系统开课计划，可得性高。

#### 2.3.3 学术活动数据

| 字段 | 类型 | 说明 |
|------|------|------|
| 活动ID | 字符串 | 唯一标识 |
| 活动名称 | 字符串 | 关键词提取 |
| 活动类型 | 枚举 | 讲座/竞赛/工作坊/读书会 |
| 主办单位 | 字符串 | 辅助信息 |
| 活动简介/摘要 | 文本 | 内容推荐的核心文本来源 |
| 主题标签 | 列表 | 人工标注关键词，比自动提取更准确 |
| 活动时间 | 日期时间 | 时效性过滤（过期活动不推荐） |
| 活动地点 | 字符串 | 辅助信息 |
| 面向对象 | 字符串 | 年级/专业范围过滤 |

**数据来源**：取决于学校是否有统一的活动管理系统。若无，可在第一期只做图书推荐和课程推荐，活动推荐等数据条件具备再加。

### 2.4 系统自产数据：用户行为日志

除以上外部导入数据外，系统运行过程中会持续自产用户行为数据。这部分数据是推荐反馈闭环的核心——学生不需要主动评价推荐好坏，行为本身已经表明态度。

| 行为类型 | 数据字段 | 含义 |
|----------|----------|------|
| 推荐列表曝光 | 学号、推荐项ID、曝光时间 | 该推荐已触达学生 |
| 点击查看详情 | 学号、推荐项ID、点击时间、来源（推荐列表/搜索/对话） | 学生对该项产生兴趣（隐性正反馈） |
| 详情页停留时长 | 学号、推荐项ID、进入时间、离开时间、停留秒数 | 停留越长，兴趣越强 |
| 详情页滚动深度 | 学号、推荐项ID、滚动百分比 | 内容被阅读的完整度 |
| 有用标记 | 学号、推荐项ID、标记时间 | 显性正反馈（强信号） |
| 跳过标记 | 学号、推荐项ID、标记时间 | 显性负反馈 |
| 收藏/预约 | 学号、推荐项ID、操作时间 | 强正反馈（有行动意图） |
| 二次回看 | 学号、推荐项ID、再次点击时间 | 持续兴趣信号 |

**核心原则**：显性反馈（有用/跳过）信号强但稀疏，隐性行为（点击/停留/回看）信号弱但量大。两者互补——隐性行为决定权重微调，显性反馈决定方向修正。

**数据存储**：行为日志表独立存储，保留30天明细数据，超过30天的滚动聚合为月统计后删除明细。

### 2.5 数据源全景

```
                    ┌──────────────────────┐
外部数据              │  借阅记录             │  ← 学生做了什么
（导入）              │  选课成绩             │
                    │  馆藏书目             │  ← 系统能推荐什么
                    │  课程目录             │
                    │  学术活动（可选）        │
                    │  学生基本信息           │  ← 学生是谁
                    └──────────────────────┘
                              │
                              ▼
                    ┌──────────────────────┐
系统自产数据           │  用户行为日志           │  ← 学生对推荐的反应
（运行中持续生成）       │  曝光/点击/停留/反馈     │
                    └──────────────────────┘
```

## 3. 业务流程

### 3.1 整体业务流程

```
学生日常行为          数据沉淀             AI加工              业务输出
───────────    ───────────────    ───────────────    ───────────────
去图书馆借书  ──→  借阅记录      ──→  兴趣关键词      ──→  个性化图书推荐
上课/考试           选课成绩            知识领域倾向           课程推荐
                                         课内外交叉对比           学习路径规划
                                         掌握度评估              兴趣画像报告
                                                                       │
                                                    ↓
                                          学生反馈（有用/跳过）
                                          学生浏览行为（点击详情/停留时长/收藏/回看）
                                          教师查看兴趣分布看板
                                          教师获取智能洞察报告
```

**反馈循环说明**：系统推荐效果由两类反馈共同驱动——

| 反馈类型 | 数据来源 | 信号强度 | 数据量 | 作用 |
|----------|----------|----------|--------|------|
| 显性反馈 | "有用"/"跳过"按钮 | 强（明确态度） | 稀疏 | 方向修正 |
| 隐性行为 | 点击详情、停留时长、滚动深度、收藏、回看 | 弱但真实（行为即态度） | 大量 | 权重微调 |

隐性行为反馈的关键逻辑：
- 学生点击了某本书的详情页 → 至少存在兴趣，即使没点"有用"
- 详情页停了30秒 → 认真看了，兴趣较强
- 过几天又回看同一本 → 持续兴趣，强正信号
- 滚动到底 → 完整阅读，推荐理由被接受
- 只停留2秒就关 → 不感兴趣，可视为隐性负反馈

### 3.2 核心业务逻辑：课内外数据交叉

系统区别于单一数据源推荐的核心逻辑在于**课内（选课成绩）与课外（借阅）数据的交叉对比**：

| 数据特征 | 业务判断 | 推荐策略 |
|----------|----------|----------|
| 课内高分 + 课外同领域大量借阅 | 深度学习型，兴趣与能力双确认 | 推该领域高阶内容 |
| 课内低分 + 课外同领域大量借阅 | 有兴趣但可能遇到困难 | 推该领域入门/趣味读物，避开进阶教材 |
| 课内选A领域 + 课外大量借B领域 | 兴趣正在迁移 | B领域优先级最高，是潜在主攻方向 |
| 课内全A领域 + 课外零借阅 | 可能仅考试驱动，缺乏自主阅读习惯 | 推与当前课程直接挂钩的参考书，先建立借阅习惯 |

## 4. 功能需求

### 4.1 学生端

#### 4.1.1 个性化推荐页（首页）

**功能描述**：学生登录后进入的第一个页面，展示个性化推荐列表。

**交互规则**：
- 分三个Tab展示：图书推荐、课程推荐、活动推荐
- 每个Tab展示Top-10推荐项
- 每条推荐卡片包含：推荐对象名称、个性化推荐理由（LLM生成）、关联度标识
- 每条推荐提供两个操作按钮："有用" / "跳过"，点击后即时反馈并回写模型
- 被标记为"跳过"的类型，后续降低出现概率
- 搜索框支持搜索具体书名/课程名，查看其推荐状态

**推荐理由示例**：
> "你这学期选修了《计算机网络》，这本书是该课程高分同学最常借的参考书"
> "你课外大量借阅心理学类图书，这门《认知科学导论》选修课匹配你当前兴趣方向"

#### 4.1.2 学生画像页

**功能描述**：展示系统对学生的学习兴趣画像，帮助学生了解自己的学习行为模式。

**展示内容**：

| 板块 | 内容 | 呈现形式 |
|------|------|---------|
| 知识领域分布 | 各知识领域的投入强度（借阅+课程综合） | 雷达图（5-8个领域顶点） |
| 兴趣关键词 | 从借阅书名和课程名提取的高频关键词 | 词云图 |
| 学习节奏 | 学期维度的借阅+选课数量变化 | 折线图 |
| 跨界兴趣区 | LLM基于画像生成的跨领域联想 | 文本卡片 |

每个图表附简短文字说明，不做评判性标签。

#### 4.1.3 推荐历史页

**功能描述**：学生可回溯自己的推荐历史。

- 按时间倒序展示历史推荐记录
- 支持按图书/课程/活动类型筛选
- 统计总推荐数、采纳数、采纳率
- 支持从历史记录中找回之前看到但忘记的推荐

#### 4.1.4 学习路径规划

**功能描述**：学生输入学习目标（如"想入门深度学习但数学基础一般"），LLM综合学生画像、馆藏状态和领域知识图谱，生成阶梯式学习路径。

**输出示例**：

> 根据你已有的数学基础：
> 第一步读《Python机器学习基础》（馆藏4本，目前在架）→ 建立编程手感
> 第二步读《深度学习入门：基于Python的实现》（馆藏2本，下周到期1本可预约）→ 建立算法直觉
> 第三步选读《深度学习》（花书，馆藏1本已被借出，可预约）
> 建议先从第一步开始，避开需要强数学背景的花书。

#### 4.1.5 智能对话助手

**功能描述**：学生端右下角的对话入口，功能边界限定为三类场景：

| 场景 | 示例 | 后台逻辑 |
|------|------|----------|
| 找书 | "有没有关于大语言模型的书" | LLM理解语义 → 推荐算法召回 → LLM包装结果回复 |
| 询问画像 | "我最近在看什么方向" | LLM读取画像数据 → 自然语言回复 |
| 课程建议 | "下学期有什么推荐课" | 推荐算法召回候选 → LLM结合画像生成推荐 |

不做开放闲聊，超出边界的问题友好拒绝。

#### 4.1.6 语义检索

**功能描述**：在推荐系统内嵌入语义检索，学生用自然语言描述需求即可匹配馆藏资源。支持模糊需求表达：

- "怎么学写代码" → 匹配编程入门书
- "写论文写不出来怎么办" → 匹配学术写作指南
- "想看点哲学入门的书" → 匹配哲学普及读物

与推荐系统共享一个检索入口，学生不需区分"搜索"和"推荐"两种路径。

#### 4.1.7 资源详情页

**功能描述**：推荐列表中的每一项都可点击进入详情页，这是学生深入了解推荐内容的唯一入口，也是系统收集隐性行为反馈的核心页面。

**页面结构（以图书为例）**：

| 区域 | 内容 |
|------|------|
| 基本信息区 | 书名、作者、出版社、出版年份、中图分类号、馆藏位置、在馆/外借状态 |
| 内容预览区 | 内容摘要/目录、封面图（如有） |
| 个性化推荐理由 | LLM生成的、针对该学生的推荐理由（与推荐列表中的理由一致，可更详细） |
| 关联推荐区 | "借了这本书的人也借了"的3-5本关联图书 |
| 操作区 | 收藏 / 预约（如已借出）/ 有用 / 跳过 |

**课程详情页和活动详情页类似**，核心要素：基本信息 + 内容介绍 + 个性化推荐理由 + 关联推荐 + 操作入口。

**隐性行为采集**：从学生进入详情页到离开，系统自动记录：

| 行为 | 采集方式 | 含义 |
|------|----------|------|
| 点击进入 | 路由跳转日志 | 兴趣触发 |
| 停留时长 | 页面进入/离开时间戳差值 | <5秒弱兴趣，>30秒强兴趣 |
| 滚动深度 | 页面滚动百分比 | 是否完整阅读 |
| 关联推荐点击 | 从详情页跳转到其他推荐项 | 兴趣延展 |
| 收藏/预约 | 按钮点击事件 | 行动意图（最强正信号） |
| 离开后回看 | 24小时内再次进入同一详情页 | 持续兴趣 |

#### 4.1.8 浏览行为反馈闭环

**功能描述**：学生一切浏览行为自动纳入推荐反馈循环。不需要学生主动评价，系统从行为中学习。

**反馈分层处理逻辑**：

```
行为信号                  强度      模型影响
─────────────            ────      ────────
收藏 / 预约              ★★★★★    该领域权重 +20%，同类资源提升优先级
停留 > 60秒 + 滚动到底   ★★★★     该领域权重 +10%
停留 20-60秒             ★★★      该领域权重 +5%
停留 5-20秒              ★★      该领域权重 +2%
停留 < 5秒               ★        该领域权重 +0%（已曝光，不提升）
点击后立即返回            ☆       该资源降权 -5%，可能推荐理由与实际不符
24小时内回看              ★★★★    该资源额外 +8%（持续兴趣强信号）
```

**冷数据衰减**：行为权重随时间衰减——30天前的行为权重减半，60天前的行为不计入当前偏好（学生兴趣会迁移，旧数据不可靠）。

**反馈闭环的可解释性**：学生可在推荐历史页看到"为什么推荐这本"的解释中包含行为反馈因素：
> "你近期多次查看过机器学习相关图书的详情，且上次在《Python机器学习》的详情页停留了2分钟，所以推荐这本进阶书。"

### 4.2 教师端

#### 4.2.1 学生兴趣总览

**功能描述**：按院系/年级维度筛选所管学生群体，查看兴趣分布全貌。

**展示内容**：

| 板块 | 内容 | 呈现形式 |
|------|------|---------|
| 知识领域热力图 | 横轴知识领域，纵轴学生人数，颜色深浅代表活跃度 | 热力图 |
| 课内外偏离度 | 课内选课多但课外借阅少的领域 vs 课外借阅多但课内选课少的领域 | 双柱对比图 |
| 资源匹配缺口 | 学生兴趣集中但馆藏复本量不足的领域 | 散点图 |

支持点击热力图领域下钻查看人数分布和年级构成，**不展示单个学生身份信息**。

#### 4.2.2 学生分群视图

**功能描述**：系统基于借阅+选课数据做K-Means聚类，将学生按行为模式分群（不按年级/专业分，而是按行为模式分）。

**分群示例**：

| 分群 | 特征 | 建议引导方向 |
|------|------|------------|
| 课外深度阅读型 | 某领域借阅量大、借阅时长长的学生 | 推荐竞赛/科研机会 |
| 课内考试驱动型 | 仅在考试周借书的学生 | 推荐该领域趣味入门书，引导课外阅读 |
| 跨领域探索型 | 借阅领域跨度大的学生 | 不做干预，保护其探索行为 |
| 无借阅休眠型 | 借书记录为零的学生 | 了解原因，定向推送图书馆资源信息 |

展示各分群的人数占比与学期变化趋势。

#### 4.2.3 智能洞察报告

**功能描述**：教师点击"生成月度洞察"按钮，LLM接收当前学生群体的兴趣分布数据、与上月的对比变化、馆藏与需求匹配数据，输出自然语言摘要。

**输出示例**：

> 本月2023级计算机学院学生的课外阅读集中在三个领域：大模型与AI（占比38%，较上月上升12%）、后端开发（占比21%，稳定）、网络安全（占比18%，较上月下降5%）。
>
> 值得注意的变化：
> 1. 大模型相关图书借阅量大幅上升，但馆藏仅有34本，与当前热度不匹配，建议采购
> 2. 3名学生在成绩中等的情况下高强度借阅AI领域图书，可能存在兴趣与课业表现落差，建议辅导员个别了解
> 3. 与去年同期相比，"考研备考"标签的学生提前了约6周开始借阅备考书籍
>
> 建议：尽快补充大模型入门级图书10-15册；关注AI方向高投入低绩点学生的学业辅导需求。

**设计原则**：不是替代教师判断，是将"看图表+做判断"的时间从半小时压缩到三十秒。

## 5. LLM应用设计

### 5.1 分工边界

| 层 | 职责 | 技术方案 |
|----|------|----------|
| 召回与排序 | 从海量候选中筛选出最相关的Top-N | 传统推荐算法（User-Based CF + TF-IDF + 余弦相似度） |
| 理解与表达 | 读懂学生画像、生成推荐解释、跨领域联想、自然语言对话 | LLM |

LLM不替代推荐算法，LLM运行在推荐算法的上层。

### 5.2 LLM功能清单

| 功能 | 输入 | 输出 | 调用时机 |
|------|------|------|----------|
| 智能推荐解释 | 学生画像 + 被推荐项信息 + 学生近期行为 | 个性化推荐理由文本 | 点击"为什么推荐" |
| 学习路径规划 | 学生画像 + 学习目标 + 馆藏候选 | 阶梯式学习路径 | 学生主动发起 |
| 跨领域兴趣发现 | 学生Top关键词 + 馆藏知识图谱 | 跨学科联想推荐文本 | 画像页自动生成 |
| 对话助手 | 学生自然语言提问 | 自然语言回复 | 学生主动发起 |
| 教师洞察报告 | 群体兴趣数据 + 对比变化 + 馆藏匹配 | 月度洞察摘要文本 | 教师主动触发 |
| 语义检索 | 学生自然语言查询 | 匹配的馆藏列表 | 搜索时触发 |

### 5.3 LLM调用策略

- 推荐解释和跨领域发现采用**离线预生成 + 缓存**策略，减少实时调用成本
- 对话助手和学习路径规划采用**流式（streaming）**输出，提升交互体验
- 教师洞察报告采用**定时预生成 + 按需刷新**策略
- 所有LLM调用设置请求超时和降级方案：LLM不可用时推荐理由降级为模板化文案，对话助手降级为关键词检索

## 6. 推荐策略设计

### 6.1 推荐算法

| 算法 | 适用场景 | 说明 |
|------|----------|------|
| User-Based CF | 发现跨领域潜在兴趣 | 基于学生特征向量计算学生间相似度，聚合Top-K相似学生的高频物品 |
| TF-IDF + 余弦相似度 | 内容精准匹配、新资源冷启动 | 学生兴趣关键词向量与图书/课程描述向量计算余弦相似度 |
| 混合排序 | 最终推荐列表 | 协同过滤结果 × α + 内容推荐结果 × (1-α)，α默认0.6 |

### 6.2 分层推荐策略

按学生数据完整度采用不同策略：

| 层级 | 数据条件 | 策略 |
|------|----------|------|
| 完整层 | 有借阅 + 有成绩 | 课内外交叉对比 + 协同过滤 + 内容推荐，完整策略 |
| 部分层 | 有借阅无成绩 | 纯借阅驱动推荐，成绩维度跳过 |
| 冷启动层 | 无借阅无成绩（新生） | 同专业同年级热门书和课推荐，4周后过渡至完整层 |

### 6.3 冷启动处理

- **新学生**：同专业同年级的热门借阅清单 + 当前学期必修课配套参考书
- **新图书/新课程**：基于内容特征与已有学生画像匹配，主动推送
- **积累周期**：开学4周后借阅数据达可用量，自动切换至完整层策略

## 7. 非功能性需求

### 7.1 性能要求

| 指标 | 要求 |
|------|------|
| 推荐准确率 | Top-10推荐中用户正向反馈占比 ≥ 75% |
| 推荐响应时间 | 单次请求 < 3秒 |
| LLM响应时间 | 流式首字节 < 2秒，完整生成 < 15秒 |
| 数据规模 | 支撑 ≥ 10,000学生，≥ 50万条借阅记录 |

### 7.2 安全要求

- 学生原始数据仅在服务端处理，前端展示时学号脱敏
- 教师端不展示单个学生详细行为数据，仅展示聚合统计
- 对话助手记录脱敏存储，定期清理
- 系统校内网部署，不暴露外网

### 7.3 可用性要求

- 核心推荐功能在LLM不可用时仍可正常运行（降级方案）
- 数据导入支持异常数据和格式错误的容错处理
- 推荐结果缓存机制，减少重复计算

### 7.4 可维护性要求

- 中图分类号→知识领域映射表支持人工维护和更新
- 推荐模型支持参数调整（混合权重α、Top-K值等）
- LLM Prompt模板可配置，便于效果调优

## 10. 术语说明
